# SHIMANAMIの酒 公開サイト 計画

이 문서가 설계와 결정의 원본이다. 진행 상황은 progress.json에만 적는다.

## 1. 무엇을 만드나
愛媛県側 しまなみ海道・ゆめしま海道 지역의 술과 造り手(사업자)를 소개하는 일본어 공개 관광 안내 사이트다. 사업자 소개가 중심이고, 지도, 체험(실제 예약 사이트로 연결), 이벤트 일정을 함께 보여준다. 내용 수정은 숨은 관리 화면에서 담당자별 비밀번호로 한다.

## 2. 누가 어디서 쓰나
- 사용자: 관광객과 지역 술에 관심 있는 사람(일본어). 관리 담당자는 회사 담당자와 후임자이며 계정 만들기가 어려운 사람도 쓸 수 있어야 한다.
- 사용 기기: 휴대폰과 컴퓨터 모두. 공개 사이트는 휴대폰 방문이 많다고 보고 두 폭을 모두 기준으로 만든다.
- 공개 범위: 공개 사이트는 누구나. 관리 화면은 숨은 주소와 담당자별 비밀번호.

## 3. 지금 만들 기능 (2단계)
1단계 시안은 2026-10-26 사장님이 틀을 승인했다. 2단계는 시안 그대로 공개 사이트 화면을 만들고, 내용은 저장소 안 데이터 파일에서 읽는다. 관리 화면과 스프레드시트 연결은 4단계다.

| 기능 | 합격 조건 |
|---|---|
| 첫 화면 | 휴대폰(폭 390)과 컴퓨터(폭 1366)에서 로고, 큰 문구, 소개문, 造り手を見る 버튼이 스크롤 없이 보인다. 로고 배경과 화면 배경 색이 같아 로고 사각형 테두리가 보이지 않는다 |
| 造り手 목록 | 컴퓨터에서 다섯 곳이 한 줄로 나란히 보이고, 휴대폰에서는 옆으로 넘겨 다섯 곳을 모두 볼 수 있다. 각 칸에 로고, 종류, 이름, 보조 표기, 지역, 설명이 보인다. 설명이 비어 있으면 설명 줄 없이 보인다 |
| 造り手 상세 | 각 造り手를 누르면 그 사업자 페이지가 열리고 주소, 전화, 공식 사이트(있을 때만), 경로를 見る 버튼이 보인다. 경로를 見る는 주소로 Google 지도를 연다 |
| 지도 목록 | 地図 칸에 다섯 곳의 번호, 이름, 종류, 주소, 전화가 보이고 경로를 見る가 주소로 Google 지도를 연다. 지도 자리에는 3단계에서 지도가 들어간다는 자리만 둔다 |
| 체험 | 종류 버튼(すべて, 酒蔵・醸造所見学, ペアリング, 文化ガイド, お酒診断, スタンプラリー)을 누르면 그 종류만 남는다. 각 체험에 사진(없으면 사진 자리), 제목, 설명, 요금, 소요 시간, 개최, 장소, 예약 버튼이 보이고 버튼은 데이터의 예약 주소를 새 창으로 연다 |
| 이벤트 | 開催予定, 終了, すべて 버튼이 동작한다. 종료일이 일본 시간 기준 오늘보다 앞이면 終了 표시와 흐린 색으로 보인다. 각 이벤트에 날짜, 제목, 내용, 일정, 詳しく見る 링크가 보인다 |
| 공통 아래쪽 | 모든 페이지 아래에 20歳未満の飲酒は法律で禁止されています。飲酒運転は絶対におやめください。 문구와 Googleアナリティクス 이용 문구가 보인다 |
| 화면 확인 | npm run build로 만든 화면을 컴퓨터 폭 1366과 휴대폰 폭 390으로 열면 시안과 같고 가로 스크롤이 없다. 두 폭의 화면 캡처가 PR에 붙어 있다. 공개 주소 확인은 7단계에서 한다 |

## 4. 나중에 할 기능
- 지도 표시 (3단계): 주소로 위치를 구해 번호 핀을 세운다. 방식은 7번 3단계 참고.
- 관리 화면과 저장 (4단계): 숨은 주소, 담당자별 비밀번호, 스프레드시트 저장, 저장하면 공개 사이트 데이터 파일 갱신.
- 사진 올리기 (5단계): 관리 화면에서 사진을 올리면 저장소에 저장된다.
- 접속 통계 (6단계): GA4 연결, 관리 화면 안에 Looker Studio 보고서.
- 회사 GitHub 이전과 정식 공개 (7단계).

## 5. 하지 않는 것
- 예약, 결제, 온라인 주류 판매, 방문자 회원가입, 별도 모바일 앱.
- 술 제품 사진. 사진은 참고용이었고 특정 제품으로 인상이 고정되므로 사이트에 넣지 않는다.
- お知らせ 칸. 이벤트만 둔다.
- 이벤트의 장소와 참가 방법 칸. 일정과 내용, 링크만 둔다.
- Cloudflare와 구독 외 유료 서비스.

## 6. 기술 구성
- 화면: 외부 패키지 없이 Node 내장 기능만 쓰는 만들기 스크립트(scripts/build.mjs)가 data 폴더 JSON을 읽어 dist 폴더에 정적 HTML, CSS, 이미지를 만든다. 화면 문구는 일본어. 명령은 npm run build(만들기)와 npm test(시험) 두 개이고 npm 패키지를 설치하지 않는다. Codex 작업 환경이 인터넷 없이도 만들고 시험할 수 있게 하기 위해서다.
- 공개 장소: GitHub Pages. 공개 사이트 반영 장치(.github/workflows/deploy.yml)가 npm run build 결과(dist)를 올린다. 이 장치는 이미 들어 있으므로 Codex는 만들기 스크립트와 package.json만 만든다. 개인 무료 계정에서 GitHub Pages는 공개 저장소에서만 쓸 수 있어, 저장소는 7단계까지 비공개로 두고 반영 장치도 그때 켠다(사장님 결정 2026-10-27).
- 데이터: 저장소 안 data 폴더의 JSON 파일(아래 데이터 칸). 2단계는 이 파일을 직접 고친다. 4단계부터는 Google 스프레드시트가 원본이고 Apps Script가 이 JSON 파일을 GitHub에 갱신한다.
- 관리 화면(4단계): 공개 사이트 안 숨은 주소의 화면이 Apps Script 웹앱에 저장을 요청한다. 비밀번호 확인은 Apps Script 쪽에서 한다.
- 통계(6단계): GA4, Looker Studio.
- 비용: 구독 외 유료 서비스 없음. Cloudflare를 쓰지 않는다.
- 소유: 지금은 zooygoo 개인 저장소에서 만들고, 대외 공개 전에 회사 GitHub로 이전한다.

### 페이지
- / : 첫 화면, 造り手, 地図, 体験, イベント를 한 페이지에 둔다.
- /makers/사업자id/ : 造り手 상세.
- 관리 화면 주소는 4단계에서 정한다.

## 7. 구축 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| 1 | 화면 디자인 시안 | 완료. docs/mockups/site-v1.html, 2026-10-26 사장님 틀 승인 |
| 2 | 공개 사이트 화면을 데이터 파일로 구현 | 3번 표의 합격 조건 전부, PR의 컴퓨터와 휴대폰 화면 캡처 |
| 3 | 지도에 주소 기준 번호 핀 표시 | 사장님이 지도 방식을 정한 뒤 상세화 |
| 4 | 관리 화면, 담당자별 비밀번호, 스프레드시트 저장, 저장 시 공개 사이트 갱신 | 관리 화면 시안 승인 뒤 상세화 |
| 5 | 관리 화면에서 사진 올리기 | 4단계 뒤 상세화 |
| 6 | 접속 통계(GA4, 관리 화면 안 Looker Studio) | 5단계 뒤 상세화 |
| 7 | 표시례 삭제, 회사 GitHub 이전, 저장소 공개 전환과 GitHub Pages 설정, 반영 장치 켜기, 정식 공개 | 6단계 뒤 상세화 |

3단계 지도 방식은 사장님 결정 대기다.
- 가: 관리 화면에서 주소를 입력하면 Apps Script가 위치를 구해 저장하고, 무료 지도(OpenStreetMap)에 번호 핀을 자동으로 세운다. 각 핀과 목록에서 Google 지도로 넘어간다. 비용 0원, 핀 관리가 자동이다.
- 나: Googleマイマップ를 만들어 사이트에 넣는다. 지도 화면이 Google 지도 모양이지만 핀은 Googleマイマップ 화면에서 직접 관리한다.

## 8. 다루는 정보와 주의
- 개인정보 포함 여부: 없다. 사업장 주소와 대표 전화는 공개 정보다. 방문자 정보는 받지 않는다.
- 비밀값 종류와 보관 장소(4단계부터): 관리자 비밀번호는 Apps Script 스크립트 속성에 해시로, GitHub 쓰기 열쇠는 Apps Script 스크립트 속성에 둔다. 저장소, 코드, 기록에는 절대 적지 않는다. GA4 측정 ID는 공개값이다.

## 9. 테스트 시나리오
정상 흐름 (사장님이 실제로 쓰는 순서)
1. 휴대폰 폭으로 사이트 화면을 열어 첫 화면에 로고와 소개문을 본다(7단계부터는 공개 주소에서).
2. 造り手를 옆으로 넘겨 다섯 곳을 보고 하나를 눌러 상세 페이지에서 주소와 전화를 확인하고 경로를 見る를 누른다.
3. 地図 목록에서 경로를 見る를 누른다.
4. 体験에서 종류 버튼을 바꿔 보고 예약 버튼을 누른다.
5. イベント에서 終了 버튼을 눌러 끝난 이벤트를 본다.

깨뜨리기 (일부러 이상하게 써 보기)
1. 데이터의 설명, 웹사이트, 사진이 빈 값인 사업자와 체험
2. 아주 긴 사업자명과 설명, 특수문자가 든 글
3. 종류 버튼 연속 누르기와 새로고침
4. 휴대폰 폭 360과 390, 컴퓨터 폭 1366과 1920에서 가로 스크롤 없이 보기
5. 종료일이 오늘인 이벤트(開催予定으로 보여야 함)와 어제인 이벤트(終了)

## 10. 화면 디자인 값
시안 docs/mockups/site-v1.html이 기준이다. 이후 모든 화면은 여기 있는 값만 쓴다.
