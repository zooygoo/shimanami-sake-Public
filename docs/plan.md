# SHIMANAMIの酒 公開サイト 計画

이 문서가 설계와 결정의 원본이다. 진행 상황은 progress.json에만 적는다.

## 1. 무엇을 만드나
愛媛県側 しまなみ海道・ゆめしま海道 지역의 술과 造り手(사업자)를 소개하는 일본어 공개 관광 안내 사이트다. 사업자 소개가 중심이고, 지도, 체험(실제 예약 사이트로 연결), 이벤트 일정을 함께 보여준다. 내용 수정은 하단 管理 링크로 여는 관리 화면에서 관리자 비밀번호 하나로 한다.

## 2. 누가 어디서 쓰나
- 사용자: 관광객과 지역 술에 관심 있는 사람(일본어). 관리 담당자는 회사 담당자와 후임자이며 계정 만들기가 어려운 사람도 쓸 수 있어야 한다.
- 사용 기기: 휴대폰과 컴퓨터 모두. 공개 사이트는 휴대폰 방문이 많다고 보고 두 폭을 모두 기준으로 만든다.
- 공개 범위: 공개 사이트는 누구나. 관리 화면은 하단 管理 링크와 관리자 비밀번호 하나(2026-10-28 사용자 요청).

## 3. 지금 만들 기능 (2단계)
1단계 시안은 2026-10-26 사장님이 틀을 승인했다. 2단계는 시안 그대로 공개 사이트 화면을 만들고, 내용은 저장소 안 데이터 파일에서 읽는다. 관리 화면과 스프레드시트 연결은 4단계다.

| 기능 | 합격 조건 |
|---|---|
| 첫 화면 | 휴대폰(폭 390)과 컴퓨터(폭 1366)에서 로고, 큰 문구, 소개문, 造り手を見る 버튼이 스크롤 없이 보인다. 로고 배경과 화면 배경 색이 같아 로고 사각형 테두리가 보이지 않는다 |

| 지도 목록 | 地図 칸에 다섯 곳의 번호, 이름, 종류, 주소, 전화가 보이고 경로를 見る가 주소로 Google 지도를 연다. 제공한 지도 원본을 자르지 않고 표시하며 01 브루워리·02 와이너리·03 리모네·04 바쿠슈·05 야기의 번호와 색을 목록에 연결한다. 목록 핀은 원본 지도의 핀 부분을 그대로 표시해 흰 원·흰 바탕의 색 숫자·글꼴·물방울 외곽까지 같아야 한다. 이미지를 누르면 원본을 크게 볼 수 있다 |

| 공통 아래쪽 | 모든 페이지 아래에는 로고와 탐색 링크, 기존 관리자 입구로 연결하는 管理 링크가 보인다(2026-10-28 사용자 요청). 2026-10-27 사용자 지시에 따라 운영·문의 등록 예정, 음주 관련 안내, Googleアナリティクス 이용 문구 세 줄을 삭제한다 |
| 비공개 확인·정식 공개 | 현재는 소유자 전용 비공개 미리보기에서 확인한다. 정식 GitHub Pages 공개와 자동 반영 확인은 7단계에서 공개 승인 뒤 진행한다 |


### 관리자와 조회 기록 합격 조건 (이번 추가 작업)

- 2026-10-28 사용자 지시: 사업자 정보는 고정으로 사용한다. 이미 만든 편집 기능은 보존하되 사업자 저장 오류 수정은 이번 완성의 선행 조건에서 제외하고, 체험·이벤트 등록·사진·화면·통계 검증을 우선한다. Draft·비공개를 유지하며 main 병합·정식 공개는 하지 않는다.
- 비밀번호는 숫자만으로도 원하는 길이로 설정할 수 있고 최소·최대 길이를 강제하지 않는다. 빈 값은 허용하지 않는다.
- /admin/에는 담당자 선택 없이 비밀번호만 보이며, 미연결 상태는 명확히 표시한다. 연결 후 올바른 비밀번호로만 편집 화면이 열리고 로그아웃·만료 세션의 저장 요청은 서버에서 거부한다.
- 로그인한 관리자가 사업자·체험·이벤트 내용을 저장하면 스프레드시트에 남고, 공개 화면을 새로 열면 반영된다. 저장 실패·잘못된 링크·날짜 역전·다른 화면의 먼저 저장한 변경은 성공으로 표시하지 않는다.
- 체험·이벤트를 새로 추가할 때 기존 항목과 같은 ID이면 원래 내용을 덮어쓰지 않고 다른 ID를 입력하라는 안내를 표시한다. 기존 항목을 선택한 수정·사진 교체·표시 해제는 같은 ID로 저장할 수 있다.
- 체험·이벤트에서 사진 파일 한 장을 선택하면 저장 전 미리 보이고, 저장 후 다시 열면 같은 사진이 보인다. 사진 교체·표시 해제와 잘못된 파일·전송 실패도 확인한다. 실제 Google·사진 저장 연결 전에는 실사용 완료로 표시하지 않는다.
- 연결한 사이트를 열면 閲覧記録에 일본 시간·날짜·페이지·이벤트 ID가 한 행 추가된다. 관리자 화면과 필터 버튼은 추가하지 않으며 같은 전송의 재시도는 중복 저장하지 않는다. 실제 시트 행 증가 확인 전에는 집계 완료로 표시하지 않는다.
- 관리 화면 안에서 일본 날짜 기준 오늘·이번 달·누적·페이지별 조회 수와 외부 예약·안내 링크 클릭 수를 구분해 본다. 이번 달은 최근 30일이 아닌 달력의 1일부터 오늘까지다. 고유 방문자 수로 표시하지 않는다. 기존 네 칸 기록은 조회로 읽고 보존한다.
- 2026-10-30 사용자 요청: 관리 화면의 閲覧数에서도 Google 시트처럼 네 핵심 통계, 일별·시간대별 차트와 사업자·체험·이벤트별 순위가 보인다. 시작일·종료일을 같은 날짜로 고르면 하루만 보고, 날짜·매일 적용할 시각 범위를 바꾸면 숫자·차트·순위가 함께 바뀐다. 잘못된 범위·빈 기록·클릭 未計測를 구분하고 폭 390·1366에서도 읽을 수 있다.

## 4. 나중에 할 기능
- 지도 표시 (3단계): 사용자가 제공한 고정 지도 이미지와 번호·색이 연결된 목록을 표시한다.
- 관리 화면과 저장 (4단계): 하단 管理 링크, 관리자 비밀번호 하나, 스프레드시트 저장, 저장한 내용을 공개 화면에 반영.
- 사진 올리기 (5단계): 2026-10-27 사용자 지시로 체험·이벤트 사진 파일 선택·미리보기·교체·표시 해제를 관리자 작업에 먼저 포함한다. 사진 원본 자산은 보존한다.
- 조회 수 확인 (6단계): 사이트에서 직접 조회 수를 집계하고 관리 화면에서 본다. 외부 분석 도구 사용을 전제로 두지 않는다.
- 회사 GitHub 이전과 정식 공개 (7단계).

## 5. 하지 않는 것
- 예약, 결제, 온라인 주류 판매, 방문자 회원가입, 별도 모바일 앱.
- 술 제품 사진. 사진은 참고용이었고 특정 제품으로 인상이 고정되므로 사이트에 넣지 않는다.
- お知らせ 칸. 이벤트만 둔다.
- 이벤트의 장소와 참가 방법 칸. 일정과 내용, 링크만 둔다.
- Cloudflare와 구독 외 유료 서비스.

## 6. 기술 구성
- 화면: 외부 패키지 없이 Node 내장 기능만 쓰는 만들기 스크립트(scripts/build.mjs)가 data 폴더 JSON을 읽어 dist 폴더에 정적 HTML, CSS, 이미지를 만든다. 화면 문구는 일본어. 명령은 npm run build(만들기)와 npm test(시험) 두 개이고 npm 패키지를 설치하지 않는다. Codex 작업 환경이 인터넷 없이도 만들고 시험할 수 있게 하기 위해서다.
- 공개 장소: GitHub Pages. main에 합쳐지면 공개 사이트 반영 장치(.github/workflows/deploy.yml)가 npm run build 결과(dist)를 올린다. 이 장치는 이미 들어 있으므로 Codex는 만들기 스크립트와 package.json만 만든다. 개인 무료 계정에서 GitHub Pages는 공개 저장소에서만 쓸 수 있다.
- 임시 미리보기 예외(2026-10-27 사용자 승인): 정식 공개 전 직접 조작 확인을 위해 Sites의 Cloudflare 기반 호스팅을 본인 한 명만 로그인해 볼 수 있는 비공개 미리보기에 한해 허용한다. 주소는 https://shimanami-sake-preview.woogie3.chatgpt.site 이며, 검증된 2단계 생성 결과를 별도 미리보기 공간에 그대로 복사했다. GitHub 저장소는 비공개로 유지하고 정식 GitHub Pages 공개 설정과 자동 반영 장치는 바꾸지 않는다. 미리보기 내용은 이후 변경 때 다시 올린다.
- 데이터: 저장소 안 data 폴더의 JSON 파일은 최초 표시와 오프라인 시험의 기준이다. 관리자 연결 뒤에는 Google 스프레드시트를 원본으로 쓰고 공개 내용만 읽는 Apps Script 응답을 화면에 반영한다. 저장할 때 GitHub 열쇠를 방문자에게 제공하지 않는다. Apps Script 실행 주소가 없으면 정적 기준 내용을 표시하며 실시간 저장·집계는 시작하지 않는다.
- 관리 화면(4단계): 사이트 하단 管理 링크로 여는 화면이 Apps Script 웹앱에 저장을 요청한다. 비밀번호 확인은 Apps Script 쪽에서 한다.
- 조회 수(6단계): 사이트 자체 집계와 관리 화면 표시. 정적인 페이지 안의 숫자나 브라우저 저장소만으로 전체 방문자의 조회 수를 집계했다고 하지 않는다. 누적 저장은 Apps Script와 Google 스프레드시트를 쓰며 실제 Google 실행 주소 연결 후 활성화한다.
- 비용: 구독 외 유료 서비스 없음. Cloudflare를 쓰지 않는다.
- 소유: 지금은 zooygoo 개인 저장소에서 만들고, 대외 공개 전에 회사 GitHub로 이전한다.
