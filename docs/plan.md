# SHIMANAMIの酒 公開サイト 計画

이 문서가 설계와 결정의 원본이다. 진행 상황은 progress.json에만 적는다.

## 1. 무엇을 만드나
愛媛県側 しまなみ海道・ゆめしま海道 지역의 술과 造り手(사업자)를 소개하는 일본어 공개 관광 안내 사이트다. 사업자 소개가 중심이고, 지도, 체험(실제 예약 사이트로 연결), 이벤트 일정을 함께 보여준다. 내용 수정은 숨은 관리 화면에서 관리자 비밀번호 하나로 한다.

## 2. 누가 어디서 쓰나
- 사용자: 관광객과 지역 술에 관심 있는 사람(일본어). 관리 담당자는 회사 담당자와 후임자이며 계정 만들기가 어려운 사람도 쓸 수 있어야 한다.
- 사용 기기: 휴대폰과 컴퓨터 모두. 공개 사이트는 휴대폰 방문이 많다고 보고 두 폭을 모두 기준으로 만든다.
- 공개 범위: 공개 사이트는 누구나. 관리 화면은 숨은 주소와 관리자 비밀번호 하나.

## 3. 지금 만들 기능 (2단계)
1단계 시안은 2026-10-26 사장님이 틀을 승인했다. 2단계는 시안 그대로 공개 사이트 화면을 만들고, 내용은 저장소 안 데이터 파일에서 읽는다. 관리 화면과 스프레드시트 연결은 4단계다.

| 기능 | 합격 조건 |
|---|---|
| 첫 화면 | 휴대폰(폭 390)과 컴퓨터(폭 1366)에서 로고, 큰 문구, 소개문, 造り手を見る 버튼이 스크롤 없이 보인다. 로고 배경과 화면 배경 색이 같아 로고 사각형 테두리가 보이지 않는다 |
| 造り手 목록 | 컴퓨터에서 다섯 곳이 한 줄로 나란히 보이고, 휴대폰에서는 옆으로 넘겨 다섯 곳을 모두 볼 수 있다. 각 칸에 로고, 종류, 이름, 보조 표기, 지역, 설명이 보인다. 설명이 비어 있으면 설명 줄 없이 보인다 |
| 造り手 상세 | 각 造り手를 누르면 그 사업자 페이지가 열리고 주소, 전화, 공식 사이트(있을 때만), 경로를 見る 버튼이 보인다. 경로를 見る는 주소로 Google 지도를 연다 |
| 지도 목록 | 地図 칸에 다섯 곳의 번호, 이름, 종류, 주소, 전화가 보이고 경로를 見る가 주소로 Google 지도를 연다. 제공한 지도 원본을 자르지 않고 표시하며 01 브루워리·02 와이너리·03 리모네·04 바쿠슈·05 야기의 번호와 색을 목록에 연결한다. 목록 핀은 원본 지도의 핀 부분을 그대로 표시해 흰 원·흰 바탕의 색 숫자·글꼴·물방울 외곽까지 같아야 한다. 이미지를 누르면 원본을 크게 볼 수 있다 |
| 체험 | 카테고리 선택 버튼 없이 모든 체험을 표시한다(2026-10-28 사용자 지시). 각 체험에 사진(없으면 사진 자리), 제목, 설명이 보이고 설명 바로 아래 예약 버튼이 데이터의 예약 주소를 새 창으로 연다. 요금·소요 시간·개최·장소 정보표는 표시하지 않는다 |
| 이벤트 | 開催予定, 終了, すべて 버튼이 동작한다. 종료일이 일본 시간 기준 오늘보다 앞이면 終了 표시와 흐린 색으로 보인다. 각 이벤트에 날짜, 제목, 내용, 일정, 詳しく見る 링크가 보인다 |
| 공통 아래쪽 | 모든 페이지 아래에는 로고와 탐색 링크, 기존 관리자 입구로 연결하는 管理 링크가 보인다(2026-10-28 사용자 요청). 2026-10-27 사용자 지시에 따라 운영·문의 등록 예정, 음주 관련 안내, Googleアナリティクス 이용 문구 세 줄을 삭제한다 |
| 공개 | main에 합쳐지면 자동으로 GitHub Pages 주소에 반영되고, 그 주소를 휴대폰에서 열 수 있다 |


### 관리자와 조회 기록 합격 조건 (이번 추가 작업)

- 2026-10-28 사용자 지시: 사업자 정보는 고정으로 사용한다. 이미 만든 편집 기능은 보존하되 사업자 저장 오류 수정은 이번 완성의 선행 조건에서 제외하고, 체험·이벤트 등록·사진·화면·통계 검증을 우선한다. Draft·비공개를 유지하며 main 병합·정식 공개는 하지 않는다.
- 비밀번호는 숫자만으로도 원하는 길이로 설정할 수 있고 최소·최대 길이를 강제하지 않는다. 빈 값은 허용하지 않는다.
- /admin/에는 담당자 선택 없이 비밀번호만 보이며, 미연결 상태는 명확히 표시한다. 연결 후 올바른 비밀번호로만 편집 화면이 열리고 로그아웃·만료 세션의 저장 요청은 서버에서 거부한다.
- 로그인한 관리자가 사업자·체험·이벤트 내용을 저장하면 스프레드시트에 남고, 공개 화면을 새로 열면 반영된다. 저장 실패·잘못된 링크·날짜 역전·다른 화면의 먼저 저장한 변경은 성공으로 표시하지 않는다.
- 체험·이벤트를 새로 추가할 때 기존 항목과 같은 ID이면 원래 내용을 덮어쓰지 않고 다른 ID를 입력하라는 안내를 표시한다. 기존 항목을 선택한 수정·사진 교체·표시 해제는 같은 ID로 저장할 수 있다.
- 체험·이벤트에서 사진 파일 한 장을 선택하면 저장 전 미리 보이고, 저장 후 다시 열면 같은 사진이 보인다. 사진 교체·표시 해제와 잘못된 파일·전송 실패도 확인한다. 실제 Google·사진 저장 연결 전에는 실사용 완료로 표시하지 않는다.
- 연결한 사이트를 열면 閲覧記録에 일본 시간·날짜·페이지·이벤트 ID가 한 행 추가된다. 관리자 화면과 필터 버튼은 추가하지 않으며 같은 전송의 재시도는 중복 저장하지 않는다. 실제 시트 행 증가 확인 전에는 집계 완료로 표시하지 않는다.
- 관리 화면 안에서 일본 날짜 기준 오늘·이번 달·누적·페이지별 조회 수와 외부 예약·안내 링크 클릭 수를 구분해 본다. 이번 달은 최근 30일이 아닌 달력의 1일부터 오늘까지다. 고유 방문자 수로 표시하지 않는다. 기존 네 칸 기록은 조회로 읽고 보존한다.

## 4. 나중에 할 기능
- 지도 표시 (3단계): 사용자가 제공한 고정 지도 이미지와 번호·색이 연결된 목록을 표시한다.
- 관리 화면과 저장 (4단계): 숨은 주소, 관리자 비밀번호 하나, 스프레드시트 저장, 저장한 내용을 공개 화면에 반영.
- 사진 올리기 (5단계): 2026-10-27 사용자 지시로 체험·이벤트 사진 파일 선택·미리보기·교체·표시 해제를 관리자 작업에 먼저 포함한다. 사진 원본 자산은 보존한다.
- 조회 수 확인 (6단계): 사이트에서 직접 조회 수를 집계하고 관리 화면에서 본다. 외부 분석 도구 사용을 전제로 두지 않는다.
- 회사 GitHub 이전과 정식 공개 (7단계).

## 5. 하지 않는 것
- 예약, 결제, 온라인 주류 판매, 방문자 회원가입, 별도 모바일 앱.
- 술 제품 사진. 사진은 참고용이었고 특정 제품으로 인상이 고정되므로 사이트에 넣지 않는다.
- お知らせ 칸. 이벤트만 둔다.
- 이벤트의 장소와 참가 방법 칸. 일정과 내용, 링크만 둔다.
- Cloudflare와 구독 외 유료 서비스.

## 6. 기술 구성
- 화면: 외부 패키지 없이 Node 내장 기능만 쓰는 만들기 스크립트(scripts/build.mjs)가 data 폴더 JSON을 읽어 dist 폴더에 정적 HTML, CSS, 이미지를 만든다. 화면 문구는 일본어. 명령은 npm run build(만들기)와 npm test(시험) 두 개이고 npm 패키지를 설치하지 않는다. Codex 작업 환경이 인터넷 없이도 만들고 시험할 수 있게 하기 위해서다.
- 공개 장소: GitHub Pages. main에 합쳐지면 공개 사이트 반영 장치(.github/workflows/deploy.yml)가 npm run build 결과(dist)를 올린다. 이 장치는 이미 들어 있으므로 Codex는 만들기 스크립트와 package.json만 만든다. 개인 무료 계정에서 GitHub Pages는 공개 저장소에서만 쓸 수 있다.
- 임시 미리보기 예외(2026-10-27 사용자 승인): 정식 공개 전 직접 조작 확인을 위해 Sites의 Cloudflare 기반 호스팅을 본인 한 명만 로그인해 볼 수 있는 비공개 미리보기에 한해 허용한다. 주소는 https://shimanami-sake-preview.woogie3.chatgpt.site 이며, 검증된 2단계 생성 결과를 별도 미리보기 공간에 그대로 복사했다. GitHub 저장소는 비공개로 유지하고 정식 GitHub Pages 공개 설정과 자동 반영 장치는 바꾸지 않는다. 미리보기 내용은 이후 변경 때 다시 올린다.
- 데이터: 저장소 안 data 폴더의 JSON 파일은 최초 표시와 오프라인 시험의 기준이다. 관리자 연결 뒤에는 Google 스프레드시트를 원본으로 쓰고 공개 내용만 읽는 Apps Script 응답을 화면에 반영한다. 저장할 때 GitHub 열쇠를 방문자에게 제공하지 않는다. Apps Script 실행 주소가 없으면 정적 기준 내용을 표시하며 실시간 저장·집계는 시작하지 않는다.
- 관리 화면(4단계): 공개 사이트 안 숨은 주소의 화면이 Apps Script 웹앱에 저장을 요청한다. 비밀번호 확인은 Apps Script 쪽에서 한다.
- 조회 수(6단계): 사이트 자체 집계와 관리 화면 표시. 정적인 페이지 안의 숫자나 브라우저 저장소만으로 전체 방문자의 조회 수를 집계했다고 하지 않는다. 누적 저장은 Apps Script와 Google 스프레드시트를 쓰며 실제 Google 실행 주소 연결 후 활성화한다.
- 비용: 구독 외 유료 서비스 없음. Cloudflare를 쓰지 않는다.
- 소유: 지금은 zooygoo 개인 저장소에서 만들고, 대외 공개 전에 회사 GitHub로 이전한다.

### 페이지
- / : 첫 화면, 造り手, 地図, 体験, イベント를 한 페이지에 둔다.
- /makers/사업자id/ : 造り手 상세.

### 관리자 페이지 구성안 (4단계 구현 전 시안 확인)

2026-10-27 사용자 요청에 따른 정리다. 2026-10-27 추가 지시에 따라 지도 결정과 별도로 단일 관리자 편집·저장·사이트 반영을 먼저 만들고 조회 기록 연결은 그 뒤에 진행한다. Google 실행 주소 배포가 끝나기 전에는 실제 연결 완료로 표시하지 않는다. 관리 화면은 일본어로 만들며 공개 사이트 방문자에게는 로그인이나 ChatGPT 계정을 요구하지 않는다. 임시 Sites 미리보기의 ChatGPT 로그인은 정식 사이트의 관리자 로그인과 별개다.

| 메뉴 | 담당자가 하는 일 | 시점 |
|---|---|---|
| ログイン | 관리자 비밀번호 입력, ログアウト. 담당자 선택 없음 | 4단계 |
| サイト設定 (제안) | 첫 화면 소개문과 공통 링크까지 관리할 경우 사용할 메뉴. 공통 설정의 저장 칸은 관리 화면 시안 확인 때 먼저 정한다 | 4단계 범위 확인 |
| 造り手 | 기존 데이터 칸에 맞춰 이름, 보조 표기, 지역, 소개문, 주소, 전화, 공식 사이트, SNS, 영업 시간, 표시 순서를 수정 | 4단계 |
| 体験 | 종류, 제목, 설명, 요금, 소요 시간, 개최, 장소, 관련 사업자, 예약 주소와 버튼 글을 추가·수정 | 4단계 |

| 写真 | 체험·이벤트 편집 안에서 사진 한 장 파일 선택, 교체, 미리보기, 표시 해제. 사업자 사진 관리는 이후 범위 | 5단계 일부 먼저 |

- 편집 흐름: 관리자 로그인 → 수정할 항목 선택 → 입력 → 필요하면 変更内容を確認 → 保存する → サイトで変更を確認. 저장 뒤에도 같은 항목을 유지한다. 저장 중에는 입력칸을 잠가 처리 도중 새 입력이 사라지지 않게 한다. 변경 내용 확인 화면에서는 저장하지 않고 돌아올 수 있다. 저장은 성공했지만 다시 읽기가 실패하면 저장 성공과 다시 읽기 실패를 구분하며 자동으로 중복 저장하지 않는다. 실패하면 성공으로 표시하지 않고 다시 시도할 수 있게 한다. 휴대폰에서도 같은 순서로 사용한다.
- 저장 구조는 기존 계획대로 입력 화면 → Apps Script에서 비밀번호·권한·입력값 확인 → Google 스프레드시트 저장 → 공개 내용 응답 갱신 → 방문자가 다음에 열 때 화면 갱신을 따른다. 비밀번호와 서버 비밀값은 공개 화면에 넣지 않는다.
- 권한: 관리자 한 명이 전체 사업자·체험·이벤트를 수정한다. 담당자 선택과 사업자별 권한 분리는 이번 범위에서 제외한다. Apps Script가 모든 읽기·저장·조회 수 확인 요청의 세션을 검사한다. 로그인 실패 횟수를 제한하고 세션은 최대 1시간 뒤 만료한다. 초기 비밀번호 설정은 지정한 Google 소유자에게만 허용한다.

### 체험·이벤트 사진 파일 등록 (2026-10-27 사용자 요청)

- 기존 저장소 보관 계획을 따른다. 새 저장 서비스와 유료 도구는 쓰지 않는다. 사진 파일은 기존 저장소의 전용 site-images 브랜치 uploads/experiences 또는 uploads/events 안에 보관하며 main, .github, assets 원본은 수정하지 않는다. 브랜치가 없으면 Apps Script가 저장 시 main 기준으로 만든다.
- 관리자에서 JPEG·PNG·WebP 한 장(원본 최대 10MB)을 선택한다. 브라우저가 긴 변 최대 1600px, 최대 256KB JPEG로 변환하여 미리 본다. 저장 버튼 전에는 서버에 보내지 않는다. 변환한 사진을 올리므로 촬영 위치 등의 원본 메타데이터를 보내지 않는다. 사진 내용은 운영자가 확인하고 술 제품 사진은 등록하지 않는다.
- Apps Script는 관리자 세션을 검사한 뒤 전용 GitHub Contents 권한의 GITHUB_IMAGE_TOKEN을 Script Properties에서만 읽어 사진을 저장한다. 저장소·브랜치는 서버 고정값이며 요청으로 바꿀 수 없다. 토큰은 공개 응답·브라우저·시트에 넣지 않는다. 사진 내용 해시를 파일명으로 사용해 같은 사진 저장 재시도는 중복 파일을 만들지 않는다.
- 시트에는 photo 경로만 저장한다. 비공개 저장소에서도 사진을 볼 수 있도록 Apps Script의 공개 내용 응답이 등록된 사진만 읽어 JPEG 데이터 주소로 전달한다. 방문자는 저장소 열쇠를 받지 않는다. Google 또는 GitHub 읽기 한도로 사진을 가져오지 못하면 해당 사진 자리만 비워 둔다.
- 사진 저장 뒤 내용 저장이 실패하면 성공으로 표시하지 않고 입력과 선택 사진을 유지한다. 표시 해제는 photo를 빈 값으로 바꾸며 기존 파일을 삭제하지 않는다. 이벤트 시트의 맨 끝 photo 칸은 처음 정상 저장할 때 추가하고 기존 8칸과 내용은 보존한다.
- Google 실행 주소 배포와 서버 전용 저장소 Contents 읽기·쓰기 권한 등록이 남아 있다. 연결 전에는 파일 등록을 비활성화하고 사진 업로드·실제 사이트 반영을 완료로 기록하지 않는다.

### 사이트 자체 조회 수 기본안 (6단계)

- 표시할 값은 페이지가 열린 횟수인 조회 수다. 별도 방문자 식별 설계 없이 고유 방문자 수라고 표시하지 않는다. 기본안은 첫 화면과 사업자 상세 화면을 각각 집계하고, 같은 페이지 안의 종류 버튼 선택은 추가 조회로 세지 않으며 새로고침은 새 조회로 센다.
- 일본 날짜 기준 일별·페이지별 누적 수를 관리 화면에 보여준다. 조회 수를 공개 화면 아래쪽에 붙이거나 분석 도구 이용 문구를 추가하지 않는다.
- 2026-10-28 통합 검증 범위는 기존 일본어 단일 편집이다. 별도 언어 데이터 칸이나 언어별 편집 화면은 현재 구현에 없으며 이번 운영 필수 범위에 새로 추가하지 않는다.
- 사이트가 조회 발생을 서버에 알리고 서버가 누적 값을 저장해야 한다. 방문자 브라우저의 localStorage 값만 더한 숫자는 전체 사이트 조회 수가 아니다.
- 기존 Apps Script와 스프레드시트를 활용하는 방법을 우선 검토하되 호출 한도, 동시 요청, 중복·자동 요청, 관리자 접속 제외, 서버에서의 요청 검증과 보관 기간을 확인한 뒤 저장 방식을 확정한다. 새 유료 서비스나 정식 Cloudflare 사용은 전제하지 않는다.
- 이번 지시에서 조회 수 저장은 Apps Script와 Google 스프레드시트로 정한다. 첫 화면과 사업자 상세를 열 때 익명 이벤트 ID와 정해진 페이지 경로만 전송하고, 서버가 일본 시간과 날짜를 붙여 閲覧記録 시트에 추가한다. 이름·IP·방문자 계정·검색어·질의 문자열은 저장하지 않는다. 같은 이벤트 ID의 1시간 이내 재전송은 한 번만 기록하고 새로고침은 새 이벤트로 센다. 관리자 페이지와 종류 버튼 클릭은 세지 않는다. 익명 공개 요청 특성상 봇과 조작을 완전히 구분한 고유 방문자 수가 아니다.

### Google 시트 이용 통계 대시보드 (2026-10-28 사용자 수정 지시)

조회 기록 실행 범위 승인(2026-10-27): 사용자가 지정한 스프레드시트 하나에 대해 Google 소유자 권한으로 실행하는 주소를 승인했다. 로그인 없는 요청은 공개 사업자·체험·이벤트 내용 읽기와 방문 기록 네 칸 추가만 허용하고, 내용 수정과 조회 기록 확인은 관리자 비밀번호 인증이 필요하다. 앞서 자동 승인 검토가 거절했던 설정에 대해 이 구체적인 범위를 사용자에게 확인받았다. 배포 준비 manifest에는 ANYONE_ANONYMOUS와 USER_DEPLOYING을 반영하되, Google 실행 주소를 실제로 배포하지 않았으므로 익명 방문 수집은 아직 활성화하지 않는다. TinyFish 설치와 도구 연결은 확인했지만 사용량 과금형이다. 2026-10-27 사용자가 유료 서비스 금지 유지를 선택했으므로 TinyFish 자동 조작과 브라우저 세션은 실행하지 않는다. 비용 예외나 충전을 다시 요청하지 않는다. Google 실행 범위에 대한 승인은 유지하며 Apps Script 자체와 스프레드시트는 무료 구성으로 준비한다. 무료 Chrome 제어 연결과 Google·GitHub 본인 확인은 2026-10-27 완료를 확인했다. Google 웹앱 배포도 완료했다.
