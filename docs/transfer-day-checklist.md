# 시마나미 사케 넘기는 날 점검표

받을 계정을 정한 날 아래 순서대로 진행합니다. 현재 진행률은 86%이며 회사 이전과 정식 공개가 남아 있습니다. [계획서의 다른 계정 이전 절차와 7단계 표](plan.md#다른-계정-이전-절차-7단계-준비-2026-11-16-정리)를 따릅니다.

## 넘기기 전에 준비

- [ ] **사장님** 운영 Google 계정으로 다시 로그인할 수 있는지 확인합니다. 비밀번호, 복구 메일·전화, 2단계 인증 수단을 확인합니다.
- [ ] **사장님** GitHub의 개인 열쇠 목록에서 `SHIMANAMI-sake-images`를 찾아 삭제하고, 비밀번호 재확인이 뜨면 직접 입력합니다. 목록에서 없어졌는지 확인합니다. 지금 사진은 내용과 같은 Google 시트 안에 있어 이 열쇠를 지워도 됩니다.
- [ ] **사장님** 받는 GitHub 계정의 이름과 종류(개인/조직), Google 계정의 메일과 종류(개인 Gmail/회사 Workspace), 넘기는 시점을 정합니다. 현재는 확인 필요입니다.
- [ ] **사장님** 아래 Google 이전 방법 중 하나를 고르고, 관리 화면 비밀번호를 후임자에게 전달할 방법을 정합니다. 비밀번호는 직접 입력하거나 후임자에게 따로 전달합니다.
- [ ] **Codex·Claude** [현재 공개 사이트](https://zooygoo.github.io/shimanami-sake-Public/), [현재 관리 화면](https://zooygoo.github.io/shimanami-sake-Public/admin/), [이용 통계 기록표](https://docs.google.com/spreadsheets/d/10MoKMuc7oLoBlgyvnn-LEu_eyX1NfMH2erNEOwSi8IE/edit#gid=90010001)를 비교 기준으로 기록합니다. 열린 오래된 PR을 확인해 끝난 건을 정리합니다.

**자동 반영 일정** 현재 계정의 GitHub 자동 실행은 12월 1일까지 멈춰 있습니다. 이전에 앞서 실행 가능한 날짜와 받는 계정에서의 실행 가능 여부를 확인합니다. Pages가 새 주소에서 실제로 열리기 전까지 새 사이트 주소 확인을 대기로 둡니다.

## 1. GitHub 저장소와 사이트 주소 넘기기 (SK-7-1)

- [ ] **Codex·Claude** 받는 계정에 `shimanami-sake-Public`과 같은 이름의 저장소가 있는지 확인합니다. 조직으로 넘길 때는 넘기는 계정이 그 조직에 저장소를 만들 수 있는지 확인합니다. 새 사이트 주소가 준비될 때까지 현재 주소를 쓰는 안내물과 링크 목록을 준비합니다.
- [ ] **사장님·받는 사람** 현재 GitHub 소유자로 로그인해 저장소 설정의 `Transfer`로 넘깁니다. 개인 계정이 받으면 받는 사람이 확인 메일에서 수락합니다. 조직이 받는 경우 필요한 권한 승인은 해당 계정에서 직접 합니다.
- [ ] **Codex·Claude** 새 저장소에서 Pages 공개 설정과 GitHub Actions 실행 여부를 확인하고, `공개 사이트 반영`을 한 번 실행합니다. 확인된 새 사이트·관리 화면 주소로 계획서, 진행 기록, 일본어 운영 안내와 안내물의 링크를 갱신합니다. 기존 Pages 주소의 자동 이동을 전제로 안내하지 않습니다. 개발 도구와 개발 관제실을 새 저장소에 다시 연결하고, 넘긴 사람이 협력자로 남아 있는지 확인합니다.
- [ ] **확인** 새 사이트에서 아래 다섯 가지 점검을 합니다. Google 이전 전에는 현재 Google 연결과 관리 비밀번호를 사용합니다. 사이트가 열리고 사업자와 공개 체험·이벤트가 예상대로 보이는지 확인합니다. 새 저장소·Pages·관리 화면 주소는 이전 후 확인 필요입니다.

## 2. Google 시트와 Apps Script 넘기기 (SK-7-2)

넘길 것은 내용·사진·조회 기록이 들어 있는 Google 시트와, 그 시트를 읽고 쓰는 별도 Apps Script 프로젝트입니다. 아래 한 가지를 실행합니다.

| 선택 | 사장님·받는 사람이 직접 할 일 | Codex·Claude에 맡길 일 |
| --- | --- | --- |
| 가. 운영 Google 계정 자체를 넘김 | 운영 계정에 로그인할 수 있는 상태로 넘기고, 받는 사람이 비밀번호와 복구 수단을 바꿉니다. | 기존 시트, 실행 주소와 관리 화면 연결을 그대로 쓸 수 있는지 확인합니다. |
| 나. 시트와 서버의 소유권을 넘김 | 받는 쪽이 개인 Gmail인 경우, 운영 계정에서 Google Drive의 두 파일을 공유하고 소유권 이전을 요청합니다. 받는 사람이 두 요청을 수락하고 새 계정에서 웹앱 배포에 필요한 Google 권한을 승인합니다. | `apps-script/Connection.gs`의 소유자 기본값과 Apps Script 설정 `OWNER_EMAIL`을 새 소유자로 맞춥니다. 새 소유자 배포의 실행 주소가 유지되는지 확인하고, 달라졌으면 `data/connection.json`의 `apps_script_url`을 바꿉니다. |
| 다. 받는 계정에서 시트와 서버를 복사 | 회사 Workspace 계정으로도 진행할 수 있습니다. 두 파일을 공유해 받는 계정에서 사본을 만들 수 있게 하고, 받는 사람이 새 웹앱에 필요한 Google 권한을 승인합니다. 새 관리자 비밀번호는 새 소유자가 직접 정합니다. | 복사한 내용·사진·조회 기록을 대조합니다. 새 시트 번호와 소유자를 `apps-script/Connection.gs`와 Apps Script 설정 `SPREADSHEET_ID`, `OWNER_EMAIL`에 맞춥니다. 새 실행 주소를 `data/connection.json`의 `apps_script_url`에 넣고 Pages에 반영합니다. |

- [ ] **Codex·Claude** 나·다 방법은 받는 계정의 웹앱이 배포한 사람의 권한으로 실행되고 로그인하지 않은 방문자도 공개 사이트를 이용할 수 있는지 확인합니다. 회사 계정의 공개 허용 여부와 이전 후 시트 번호·실행 주소·기록표 접근 권한은 확인 필요입니다. 실행 주소가 바뀌었다면 자동 반영이 성공한 뒤 새 사이트에서 시험합니다.
- [ ] **사장님·받는 사람** 비밀번호를 새로 정할 때는 기존 `PASSWORD_HASH` 값이 있으면 Apps Script 설정에서 지웁니다. 운영 Google 소유자로 로그인한 상태에서 해당 Google 웹앱을 직접 열어 「管理者パスワードの初期設定」을 진행합니다. 완료 후에는 사이트 안 관리 화면으로 돌아와 새 비밀번호로 로그인합니다.
- [ ] **확인** 아래 다섯 가지 점검을 모두 합니다. 수정 내용과 신규 사진이 이전한 시트에 들어가고, 새로 발생한 조회 기록도 운영에 쓰는 시트의 「閲覧記録」에 들어가는지 확인합니다.

## 3. 정식 공개하고 자동 반영 확인 (SK-7-3)

- [ ] **사장님** 정식 주소와 공개 시점을 확인하고 공개를 승인합니다. 정식 주소와 공개 시점은 승인 전까지 확인 필요입니다.
- [ ] **Codex·Claude** 승인 후 정식 주소를 안내물과 링크에 반영합니다. 기본 브랜치 `main`의 승인된 변경 뒤 `공개 사이트 반영`이 자동으로 성공하고, 정식 주소에 그 변경이 보이는지 확인합니다. 남은 오래된 초안 PR을 정리합니다.
- [ ] **확인** 정식 주소에서 아래 다섯 가지를 다시 확인합니다. 휴대폰에서도 표시를 확인하고, 테스트에 사용한 내용과 사진을 원래대로 돌립니다. 자동 실행이 계속 멈춰 있다면 자동 반영 항목은 대기 상태로 둡니다.

## 각 단계 뒤 확인할 다섯 가지

Codex·Claude가 확인을 맡고, 로그인과 비밀번호 입력이 필요한 곳은 사장님 또는 받는 사람이 직접 합니다. 공개 중인 항목에 쓰기 시험을 할 때는 먼저 사용할 항목과 변경 내용을 정하고, 시험 직후 원래대로 돌립니다. 공개 체험이나 이벤트가 아직 없다면 운영 화면의 준비 안내를 확인하고 비공개 시험 항목으로 저장을 확인합니다.

- [ ] **사이트 화면** 새 공개 주소를 열어 사업자 상세, 공개 대상 체험·이벤트, 등록된 사진을 확인합니다. 공개 항목이 없는 칸은 「現在ご案内できる情報を準備中です」를 확인합니다.
- [ ] **관리 화면 로그인** 공개 사이트의 「管理」 링크로 이동해 「パスワード」를 입력하고 「ログイン」을 눌러 항목 목록이 열리는지 확인합니다.
- [ ] **내용 저장** 시험 항목의 문구를 수정해 「変更内容を確認」과 「この内容で保存する」를 누릅니다. 같은 항목을 다시 열어 문구가 남는지 확인하고, 공개 항목이라면 「サイトで変更を確認」으로도 대조합니다.
- [ ] **사진 저장** 시험 항목에 새 사진을 골라 저장하고, 관리 화면에서 다시 열어 미리보기를 확인합니다. 공개 항목이라면 사이트 표시도 확인합니다. 시험을 마치면 원래 사진으로 교체하거나 시험 사진의 표시를 해제하고 저장합니다.
- [ ] **조회 기록 증가** 운영 기록표에서 오늘의 마지막 조회 기록을 확인한 뒤 공개 사이트 첫 화면 또는 사업자 상세를 새로 엽니다. 기록표의 「閲覧記録」에 일본 시간 기준 새 행이 생기고, 관리 화면 「閲覧数」에서 「今日」를 다시 눌러 「サイト閲覧数」가 늘었는지 확인합니다.
